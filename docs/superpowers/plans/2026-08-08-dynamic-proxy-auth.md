# AGY 动态代理与登录处理

## 目标

让桥接器在每次 AGY 调用前使用当前可用的本地代理，同时保持 AGY 自己的登录状态。代理切换不应被误判为需要重新登录；真正的认证失败必须停止调用并给出可执行的登录提示。

## 实施范围

- 在 `agy_runner` 中解析 `AGY_PROXY_URL`、`PROXY_URL`、现有代理环境、Windows 系统代理和常见本地代理端口。
- 运行时每次调用解析一次；自动发现结果缓存 60 秒，不启动后台服务或轮询线程。
- 将同一份环境传递给普通 subprocess、PTY fallback、Windows 可见终端、异步任务和协作任务。
- 直接 AGY 调用返回非零诊断时不再启动第二个 PTY AGY 进程，避免认证或网络失败造成重复执行。
- 将失败分类为 `network`、`authentication` 或 `unknown`，并返回 `AGY_PROXY_ERROR`、`AGY_LOGIN_REQUIRED` 或 `AGY_FAILED` 前缀。

## 恢复行为

- 网络、连接或超时错误只提示检查代理/TUN；下一次调用会重新探测。
- 明确的认证错误停止当前调用，提示用户通过可用代理运行 `agy` 完成登录。
- 用户确认登录完成后由上层重试原任务一次；桥接器不自动登录、不无限重试。
- 桥接器不读取、存储或删除 OAuth 凭据。
